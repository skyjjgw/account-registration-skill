# 账号注册与收码

通过当前可观察的网页状态完成用户授权的注册，并留下可核对的结果。技能提供决策流程，不是免登录、免验证或保证成功的注册程序，也不依赖 AI 后台常驻。

## 先确定本次范围

从当前请求、已明确授权的历史和现有进度中确认目标网站、使用者、账号/邮箱来源、数量以及完成标准。可沿用适用于本次操作的授权，不重复询问已回答的问题。历史中的账号批次、统一密码、协议同意、API 密钥创建要求不能自动扩大到另一个网站、使用者或新批次。

用户指定具体账号就使用该账号。未指定批量数量时，先完成一个明确授权的测试账号，不自行扩展为持续注册。多账号需符合网站规则及用户授权；不要通过更换身份、邮箱、网络或账号规避配额、赠送额度限制或平台防滥用措施。

只读取相关站点参考：
- Devin：读取 [references/devin.md](references/devin.md)。
- TypeSafe：读取 [references/typesafe.md](references/typesafe.md)。
- 涉及邮箱收码、编号或中断恢复：读取 [references/mail-and-progress.md](references/mail-and-progress.md)。

## 选择执行方式

优先使用当前环境提供的专用接口或已连接的浏览器工具。网站官方公开 API 只有在已确认支持对应操作、具有所需授权且不绕过限制时才用于该操作。区分网站注册 API、浏览器自动化 API、工作台执行接口：工作台的 replay 命令仍可能在底层打开浏览器，并不证明网站提供注册 API。

使用浏览器工具前确认它能识别目标标签页、实际网址和表单；仅看到窗口标题不等于可操作。采用本轮可观察的元素定位，不把历史 DOM、截图坐标或参考文档中的按钮名称当成当前事实。使用 Windows Computer Use 时读取该工具的技能说明；遵守工具自身的恢复和停止规则。

如果工具因无法核实网址或安全检查而阻断，不能改用低层脚本、隐藏接口、CDP 或关闭检查来继续同一个受阻操作。明确报告阻断及已完成范围，保留进度；连接修复后再继续。普通临时技术故障按工具允许的恢复流程处理，避免连续无变化重试。

## 执行和恢复

1. **识别当前状态**：注册入口是否已经跳转到登录后的主页？若是，标为“已有登录会话”，不得算作本次新注册成功。为新测试账号使用允许的独立会话，保留用户正在使用的标签页和未保存流程。
2. **准备邮箱**：确认本账号有权使用且实际可收信。生成邮箱字符串不等于创建了邮箱；用户要求新建邮箱时，先完成邮箱创建并验证可访问收件箱。
3. **发码**：在注册页填写本次账号并提交一次。记录请求开始时间及页面状态。必须看到发码成功/验证码输入页面或等效证据；仅看到人机验证完成不代表已发码。如果验证后还需“继续”，在观察当前页面后完成后续步骤。
4. **保留注册页并收码**：使用另一个标签页读取本次邮件；返回时复用原注册标签页和会话，不重新 goto 注册网址。邮箱筛选和验证码有效性规则见引用文件。
5. **完成设置**：根据实际页面填写验证码、必要资料以及授权范围内的设置；新增协议、付费动作或人机验证依照当前工具要求和已有授权处理。需要用户参与时只说明那个具体阻断，保留其余工作。
6. **核实结果**：网站出现明确的账号创建/设置完成状态，并能确认当前账号身份，才记为成功。导航成功、点击无报错、脚本退出码 0、生成 API 字符串或已有会话跳转均不单独作为成功证据。

收到“停止”就停止新增外部提交并记录当前状态；不自行继续批次。对提交超时、页面崩溃或中断的账号，先通过现有页面、邮件或正常登录路径核对是否已经创建，不能直接再次注册。

## 验收和交付

把以下结果分开记录：
- 配置/代码检查通过；
- 本地模拟流程通过；
- 真实网页的具体步骤通过；
- 新账号完整注册与身份核验通过；
- 录制结果及导出程序独立回放通过。

用户只要求真实注册时，不扩展为重写编辑器或安装一套新框架。用户要求录制器验收时，必须实际确认动作进入记录；在另外一个浏览器完成注册不能证明录制成功。

最终简短报告：完成/待核对/失败数量、完成到哪一步、具体阻断、非敏感结果文件位置。若用户要求账号密码文件，单独在用户指定的本地位置保存并避免放入共享源码包；不要把密码、验证码、会话 Cookie 或 API 密钥写进本技能、通用日志或可分享的测试材料。
