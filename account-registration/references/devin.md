# Devin 参考案例

来源：当前用户对话中截至 2026-09-27 的操作记录。以下是经验与验证范围，不是固定的最新网页规范。

- 注册入口：`https://app.devin.ai/auth/signup`。
- 曾使用邮箱验证码路径；某次打开注册入口直接进入 `/org/...`，说明存在已登录会话，不能证明本次新建账号。
- 用户曾要求选择免费方案，但当前页面是否提供、名称及必要设置未得到完整复核。只在实际看到该选项时按授权选择；不能把假设的免费方案按钮写进真实验收结论。
- 历史邮件标题曾为 `Your Devin Login Code`，发送者曾为 `no-reply@cognition.ai`。仅作筛选线索；必须核对当前发件域名、收件人和发送时间，不能仅凭标题接受。
- 曾在邮箱看到其他收件人的旧 Devin 邮件，不能因为在同一收件箱或网页显示了六位数字就使用。
- 打开当前官方 API 文档并核对能力后再考虑接口：`https://docs.devin.ai/api-reference/overview`。历史检查没有确认公开的自助注册接口；组织用户管理/邀请和创建独立注册账号不是同一操作。

## 本案例中没有完成的验收

项目曾真实回放“打开 Devin 注册页”，其余邮箱登录、新邮件筛选、填码、提交、方案选择并未完整验收。工作台的示例定位如 `[data-configure="..."]` 是占位符，不是抓取到的真实定位。已有单元测试或模拟网页通过不能消除这些缺口。

## 下次实际操作

观察注册表单并识别邮箱输入和提交方式 → 记录发码状态与时间 → 保持原标签页 → 另开邮箱标签页并筛选本次邮件 → 返回原页按实际输入控件填写（单框或多格需现场确认） → 完成实际出现的设置 → 核对当前账号身份。

不要默认需要密码：是否提供密码输入由当前页面决定。用户提供的密码只有在相应网站确实需要、且适用于本次账号时才使用。
